# PROPOSAL-0014 PR2 検証結果 (2026-11-22)

stock-analysis-agent を設定で gateway 経由にし、Mac mini の Docker で実際の分析を 1 件流した。
本番と同じ Dockerfile のイメージ (検証用のタグ) を `llm-gateway-agents` ネットワークに入れ、
gateway で発行した検証用のキーと定額プランのトークンで呼んだ。EDINET は切った (Brave Search の MCP は使う)。

## 結果

| 確かめたこと | 結果 |
|---|---|
| 分析が gateway 経由で最後まで通る | 通る。3 ターン、73 秒、レポート 5,884 文字。Brave Search の MCP を 1 回呼んだ |
| 1 本目が 400 になって送り直さない | gateway への `/v1/messages` は 4 本とも 200。`modelOverrides` が効いている |
| Langfuse で 1 セッションにまとまる | trace ID で引くと観測 4 件 (呼び出しごとのトレース 4 本) が 1 セッションに入る。モデルは `claude-opus-5-5` |
| gateway を通らない呼び出しがない | キーの利用額 0.2673 ドルが、Agent SDK の `total_cost_usd` と一致する |
| キーの制限 | 許可する別名は `stock-analysis` / `stock-analysis-next`、30 日で 100 ドル、毎分 30 回 |
| 判断の読み取り | 最後の行の「総合判断: 強気 / 確信度: 中」を `bullish` / `medium` として保存 |
| 予測帯の保存 | 基準日 2026-11-20 の終値 3,312 円、21 営業日先 (2026-12-21) の P10〜P90 を保存 |

## 決めたこと

| 項目 | 内容 |
|---|---|
| 設定 | `LLM_GATEWAY_URL` を入れたときだけ gateway 経由にする。空なら従来どおり直接 (GCP は PR4 まで直接) |
| モデル名 | `LLM_MODEL` は CLI が知っているモデル ID、`LLM_GATEWAY_MODEL` は gateway の別名。gateway 経由のときは `modelOverrides` で前者を後者に対応付ける |
| ツール | `permission_mode="bypassPermissions"` のまま、`disallowed_tools` で Bash・Write・Edit などを禁止する |
| 判断の形式 | レポート最後の行に「総合判断: 強気 / 確信度: 高」(判断は強気・中立・弱気、確信度は高・中・低)を書かせる。読み取れないときは空のまま保存し、警告ログを出す |
| 保存先 | `reports` に列を足す (Alembic `0004_report_evaluation`)。以前のレポートは空のまま |
| 死活監視 | `LLM_GATEWAY_URL` があるとき、gateway の liveliness を監視項目 `llm-gateway` に足す |
| 切り替え | `cutover-to-local` は backend より先に gateway を起動する。gateway 一式の移行 (Langfuse のデータなど) は PR5 |

## 残り

- ローカル本番の `config/local.env` を作るときに `make key` で本番用のキーを発行する。検証用のキー `stock-analysis-agent-pr2-test` は不要になったら消す
- Mac mini 上で分析 2 件を同時に流したときのメモリ (ローカル本番の切り替え時)
- 中立とみなす幅を過去の分析に当てて決める (PR3)
- GCP の Cloud Run から VPC 経由で gateway を呼ぶ (PR4)
