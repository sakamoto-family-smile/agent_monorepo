## A1. 申込ナビ PDF P19-P20 視覚確認 (最重要発見)

設計書 (保活ドキュメント §38.3) に未解決として残されていた 2 件の不確実点について、
PDF の doc page 19-20 (PDF page 22-23) を `pdftotext -layout` で抽出した結果、
**両方とも解消** + **設計書の §16 / §17 / §18 を一部修正する必要が判明**。

### A1-1. 不確実点 (a): B 優先順位「H」の中身 → **解消: H は存在しない**

PDF 原文 (doc P20) の B 優先順位の欄:

```
優先     要 件
高      Ａ   災害
↑      Ｂ   その他
↑      Ｃ   ひとり親
        Ｄ   疾病･障がい
        Ｅ   出産
        Ｆ   就労
        Ｇ   介護・看護
↓      Ｉ   就学
↓      Ｊ   就労内定(開業予定)
低      Ｋ   求職中
```

→ **A〜K のうち H が意図的にスキップされ、合計 10 階層**。
保活ドキュメント §18 で「A〜K の 11 階層と推定したが H だけ取り損ねた可能性」と
書かれていたが、**H は元から存在しない**。

**実装への反映**:
- `rules/reiwa8/priority.yaml` で 10 階層 (H なし) として定義
- 設計書 §18 の表から「H: ※不明」行を削除し、10 階層であることを明記

### A1-2. 不確実点 (b): 「児童相談所通知 +20」の解釈 → **解消: A-1 基礎点数の「その他」 20 点**

PDF 原文 (doc P19, A-1 基礎点数 (基本) の表内):

```
ひとり親世帯  ひとり親世帯で、保育施設入所により自立の促進が図られる場合              11
その他       児童相談所からの通知などにより、児童福祉の観点から、特に保育施設入所の必要性が高いと判断した場合   20
```

→ **「20」は A-1 基礎点数 (基本) の独立した類型「その他」に属する点数値**。
保活ドキュメント §38.3 で挙がっていた解釈 1 (A-2 加算) / 解釈 2 (B 優先順位) の
**いずれでもなく、解釈 3: A-1 基礎点数 = 20 点が正解**。

**実装への反映**:
- `rules/reiwa8/basic_scores.yaml` に以下の 2 行を追加:
  - `basic.single_parent`: 11 点 (ひとり親世帯特例)
  - `basic.other.child_welfare`: 20 点 (児童相談所通知等)
- 保活ドキュメント §17 の A-2 加減算表から「児童相談所通知 +20」を削除
- §16 の A-1 基礎点数表に「その他 (児童相談所通知)」「ひとり親世帯」の 2 行を追加

### A1-3. 副次的に発見された修正点

PDF 抽出により、設計書と齟齬がある部分を 4 件発見:

**(i) ひとり親 11 点の構造**
設計書 §17 では「ひとり親世帯特例: A-1 = 11 点固定」と注記扱いだが、
**実際は A-1 基礎点数 (基本) の表内に独立した類型として存在**。実装上は
父母の点数を低い側採用するロジックの **前段** で「ひとり親なら 11 点で確定 + B = C」
の早期 return を入れる。

**(ii) 転園申請の 6 ヶ月優先ペナルティ (P20 注意事項①)**
> 転園元の保育施設に入所してから 6 ヶ月間は、他の新規に入所を希望する児童を優先して内定します。
> ※転居・きょうだいが別々に入所している等のやむを得ない事情がある場合を除く

→ 保活ドキュメント §12 では「転園希望者は副次対象」と簡記のみ。
**6 ヶ月ペナルティのルールは Score-Calc MCP の DSL とは独立した「内定ロジック側の特例」として**
実装する必要 (ScoreBreakdown には影響しないが、StrategyAgent の勝率予測には影響)。

**(iii) 内定辞退ペナルティの正確な期限 (P20 注意事項③)**
> 令和 5 年 4 月以降の審査にて内定辞退後、新たに入所申込みをした場合、
> 再度入所決定するか、減点対象の期間を経過するまで基礎点数が 2 点減算

設計書 §17 ⑨ では「3 年度間」と固定だが、PDF では「**再度入所決定するか、減点期間
経過するまでのいずれか早い方**」となっている。実装は OR 条件で書く。

**(iv) 就労内定の細目構成**
PDF では就労内定が **3 段階 (140h+ → 6 / 64h+ → 5 / それ以外 → 4)**。
設計書 §16 と一致するが、「上記以外の状況で内定」の点数 4 点は YAML DSL では明示要。

#### `r4-4nyuusyonaiteisisuu.pdf` の内容確認結果

- 3 ページ・220 KB・120+ 施設収録
- タイトル: 「令和４年４月入所（1 次）入所内定指数（複数人入所施設のみ）」
- 各セルの形式: `<基礎点数><優先順位><調整項目>` (例: `10F11` = 基礎点 10、優先順位 F (就労)、調整 11)

#### Score-Calc / Strategy 設計への影響 (重要)

設計書 §9.5 の **3 段階分類のみ**モデルから、**ハイブリッドモデル**にアップグレード可能:

- **過去基準 (令和 4 年)**: 施設×クラス別の正確な最低内定指数 → 「過去にこの指数で入れた」事実
- **直近 3 年 (令和 5-7 年)**: 申込数 / 定員 / 空き状況から 3 段階分類 (推定値)
- **トレンド分析**: 令和 4 年からの倍率変動を施設単位で追跡可能

StrategyAgent の応答品質が大きく上がる。例:
> しんめいはじめ保育園 1 歳児クラスは、令和 4 年は最低指数 10F11 (= 基礎点 10、調整 11)
> で内定が出ました。令和 5-7 年は具体指数は非公表ですが、倍率は 2.4 倍前後で推移しており、
> 同程度と推定されます。あなたの指数は 12 (基礎 10 + 調整 2) なので、近年も**有力な候補**です。

これは「3 段階分類 = 超人気/人気/入りやすい」だけの応答より遥かに価値がある。

**proposal 0005 への反映**: §9.5 を 3 段階分類モデルから **ハイブリッドモデル** に書き換え、
Plan MCP の `get_facility_competition()` に `historical_minimum_index_2022` フィールドを追加。

## A3. robots.txt / sitemap.xml → **robots.txt 不在 / sitemap.xml は存在**

### A3-1. robots.txt: HTTP 404

```
HTTP/1.1 404 Not Found
```

藤沢市は `robots.txt` を提供していない。デフォルト解釈では全リソース許可だが、
**明示的な許可表明は存在しない** ため、礼儀として以下を徹底:

- User-Agent 明示 (連絡先 URL 含む)
- 同時接続 1
- リクエスト間隔 3 秒以上
- `If-Modified-Since` / `ETag` での差分取得
- 深夜帯 (03:00 JST) のバッチ集中
- Wayback Machine 経由の取得は別カウント (元サーバに負荷をかけない利点)

### A3-2. sitemap.xml: 約 1,100+ URL

- 形式: 標準 `<urlset>` (XML)
- 規模: 約 1,100+ URL を含む (主要全カテゴリ)
- `<lastmod>` タグなし → 個別 URL の更新日時は HEAD リクエストで `Last-Modified` ヘッダを参照

**LINE bot のクロール起点として有効**。
保活ドキュメントが当初想定していた `sitemap.html` (人間用) より、
`sitemap.xml` (機械用) を起点にする方が網羅性高い。

|---|---|
| 緊急情報 RSS | 存在 (緊急情報セクション内) |

## A4. 認可 / 認可外施設一覧 HTML 構造 → **pandas.read_html() で部分対応可、リンク URL は別途**

### A4-1. 認可保育施設一覧

| テーブル | 施設数 |
|---|---|
| 公立保育所 | 13 |
| 法人等保育所 | 88 |
| 認定こども園 | 6 |
| 小規模保育事業 | 19 |
| 家庭的保育事業 | 2 |
| **合計** | **128** |

- 列: 施設名 / 所在地番 / 電話番号 (法人等以降は + 外部リンク列)
- 表記ゆれ: 「(分園)」、丸印「○」「〇」混在、住所内の「ビル」「ハイツ」表記
- pandas.read_html() で 3〜4 列テーブル抽出可、ただし**ハイパーリンク URL は喪失**
  → BeautifulSoup で別途リンク抽出するパイプラインが必要

**設計書との突合**: 保活ドキュメント §2.1 では「認可約 120 施設」と概数記載 → **正確には 128 施設**。

### A4-2. 認可外保育施設一覧

| テーブル | 施設数 |
|---|---|
| 藤沢駅周辺 | 12 |
| 辻堂駅周辺 | 10 |
| 湘南台駅周辺 | 6 |
| その他駅周辺 | 4 |
| **合計** | **32** |

- 列: 施設名 (類型) / 所在地 / 電話番号 / 定員
- 類型は施設名後の括弧内に「藤沢型 A 型 / B 型 / C 型 / 企業主導型 / その他」
- 所在地欄に「駅北口・徒歩 7 分」のような最寄り駅+徒歩分数が **混在**
  → 正規表現でパースする必要あり

**設計書との突合**: 保活ドキュメント §2.1 では「認可外約 40+ 施設」 → **正確には 32 施設**
(駅エリア別 4 テーブルに分散)。
