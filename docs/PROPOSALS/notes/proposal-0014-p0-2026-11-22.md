# PROPOSAL-0014 P0 検証結果 (2026-11-22)

手元 (開発機の Docker) で LiteLLM Proxy v1.108.3 と Langfuse v4.76.0 を立て、
Claude CLI 2.1.319 と claude-agent-sdk 0.2.174 から gateway 経由で定額プランのトークンを使って呼んだ。

## 結果

| 確かめたこと | 結果 |
|---|---|
| 定額プランのトークンとバーチャルキーを一緒に送る | 通る。`x-litellm-api-key` で gateway が認証し、`Authorization` のトークンを Anthropic に渡す。懸念していた 401 ([BerriAI/litellm#29190](https://github.com/BerriAI/litellm/issues/29190)) は 2026-08 に修正済み |
| 使えるモデルの制限 | 許可した別名 `stock-analysis` は通り、`claude-opus-4-6` を直接指定すると 403 |
| ツール呼び出しとストリーミング (Agent SDK) | Read ツールを含む 2 ターンの分析が通る。メッセージの流れ (System / Assistant / User / Result) は直接呼びと同じ |
| プロンプトキャッシュ | 効く。同じ分析の 2 回目はキャッシュ読み出し 33,062 トークン、新規書き込み 0。1 時間 TTL のキャッシュも作られる |
| Langfuse への記録 | v4 は OpenTelemetry だけを受ける。LiteLLM の callback を `langfuse_otel` にすると届く |
| 分析単位のまとまり | `x-litellm-trace-id` が Langfuse の session ID になる。トレースは呼び出しごとに分かれるので、分析 1 回 = 1 セッションとして扱う |
| スコア・データセット | スコアの書き込み (`sessionId` 指定)、データセット作成、Annotation Queue の API は使える。従来のスコア・トレース読み出し API は v4 では使えない |
| 廃止日の取得 | LiteLLM のモデル情報に Vertex AI の Opus 4.6 の廃止日 (2027-02-05) がある。Anthropic API 側の項目には廃止日がない |
| Langfuse のバックアップと復元 | 停止 → volume を tar → 別の volume に展開 → 起動で、観測データとデータセットが戻る。データが少ない今は停止 5 秒・バックアップ 3 秒・復元 2 秒・起動 10 秒 |
| メモリ | gateway 一式で約 3.2 GB (Langfuse web 1.3 GB、worker 0.7 GB、LiteLLM 0.6 GB、ClickHouse 0.4 GB ほか) |

## 見つかった問題と対応

| 問題 | 対応 |
|---|---|
| CLI が別名 `stock-analysis` を未知のモデルとして扱い、system 役のメッセージを送って 400 になり、送り直す (毎回 1 本余計) | Claude Code の設定 `modelOverrides` で `{"claude-opus-5-5": "stock-analysis"}` と対応付ける。Agent SDK では `ClaudeAgentOptions(settings=...)` で渡す。別名の向き先を変えたら、この対応付けも合わせて変える |
| 提案書は Langfuse v3 を前提にしていた | v4 にする。トレースは OpenTelemetry、評価サービスは自分で付けたスコアを自前の表に持つ (v4 では読み出せないため) |
| gateway と Langfuse の env ファイルの両方に `POSTGRES_PASSWORD` があり、後から読んだ値で上書きされた | gateway 側を `LITELLM_DB_PASSWORD` にした |

## 費用の参考

LiteLLM のモデル情報では、Opus 5.5 は Opus 4.6 より単価が低い (100 万トークンあたり 入力 5 → 4 ドル、キャッシュ読み出し 0.5 → 0.2 ドル、出力 25 → 20 ドル)。
評価データセットで質に差がなければ、`stock-analysis` を Opus 5.5 に替えると費用も下がる。

**決定 (2026-11-22)**: `stock-analysis` の向き先を Opus 5.5 にする。`modelOverrides` も `{"claude-opus-5-5": "stock-analysis"}` に合わせる。
Agent SDK からの 2 ターンの呼び出しで動作を確認した。

なお Opus 5.5 は検証で `Bash` ツールを使った。`permission_mode="bypassPermissions"` では `allowed_tools` が使えるツールを絞らないため、PR2 で `disallowed_tools` に Bash・Write・Edit などを入れる。
